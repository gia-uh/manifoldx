Web target, plan 5b: events and widgets

The second of slice 5's three plans. Frame code in the page gets engine.emit and handlers that run, the desktop's input events with their payloads, a frame event with engine.elapsed, a wall clock read through time.time(), random.Random bit for bit, and the five widgets a phone app needs: Button, Slider, Toggle, Image and a new Joystick, which lands on the desktop first. A page that frames the export talks to it through events. It ends with examples/web_crowd.py carrying a panel of all five widgets and a handler per event, replayed with no mismatch in Node and in Chromium, where Playwright drives each widget with a real pointer.

goalExport examples/web_crowd.py with a second panel: a Button throws a wave, a Slider sets gravity, a Toggle turns the spin on and off, a Joystick blows a wind over the boxes, an Image shows an SVG. Handlers on frame, the seven input events, every widget event and an app event (fell) keep counts in engine.state. The Python, Node and Chromium replays deliver the same events in the same order, frame by frame. architectureOne event queue per side, in the desktop's order (Engine._draw_frame, src/manifoldx/engine.py:1238-1247): the frame event, then what was emitted during the previous frame, then the events that came in since. The replay frame gains events, the input events and outside emits the page saw, in order, and clock. A pointer event over a widget carries the widget and the pointer's place inside it, because the page's DOM is its hit test; the desktop's GUI bridge gets a seam so the Python replay reads that target instead of hit-testing its own layout. Widget events then come out of the desktop's own widget code in Python, and out of a port of it in manifoldx.js, one frame after the pointer event, as on the desktop. techPython 3.13 and numpy 2; plain ES modules; Node 20+ for node --test and the replay; three.js 0.186.1 as vendored; Playwright with Chromium in the existing browser CI job on lavapipe, with a touch context and the DevTools protocol for two pointers at once. spec.knowledge/analysis/2026-11-07-web-target-slice5-design.html (approved; sections 02, 06, 07, 10, 12 and 13, Q1, Q4 and Q5 of section 16) builds onplan 5a (merged as #166), and plans 1 to 3 before it. Global constraints

  • Functional parity (spec section 02): every runtime feature the page gains behaves as the desktop's. Where the desktop lacks a form the page needs (the Joystick, a capture per pointer, arrow keys on a Slider), it lands on the desktop first, in tasks 1 and 2, with desktop tests.
  • One event queue, the desktop's order: frame event, then the emits of the previous frame (handlers' and systems', widget events included), then the input and outside events since then (src/manifoldx/engine.py:1238-1247, src/manifoldx/events.py:133-137). An emit during delivery waits for the next frame.
  • A widget's value changes before its event is queued, as in src/manifoldx/gui/slider.py:56-66 and toggle.py:35-37.
  • No app JavaScript. The host page of Q1 talks to the export only through events (spec section 06).
  • manifoldx.js and pyrt.js import neither three.js nor a DOM name, so the Node replay keeps working. The DOM work is in input.js, gui.js and browser.js.
  • Every float both sides compute from a pointer goes through + - * / and sqrt only (never hypot, whose last bit differs between libms), so replays compare exactly.
  • An export error names the Python file and line, and what to write instead where one form exists, as the subset's errors do today.
  • Node and Playwright are test dependencies only; tests skip with node not found, playwright not installed or chromium not installed, and the browser job fails on any skip.
  • Shared host: each task's verify runs only the tests covering it. make test and the browser job run in CI.
  • manifoldx is public: no consumer's repository, people, places, domains or machines in code, tests, commits or PR text. Say "the second consumer", "a third consumer".
  • Commits are conventional and end with the co-author line; stage files by name; scratch goes under pytest's tmp_path or the system temp dir, never in the repo.

Review focus

  • A drag that leaves its widget. A pointer goes down on the Slider, leaves the panel and comes up over the 3D view: the Slider keeps the capture, its moves and its commit use the pointer's place relative to the Slider (fractions below 0 or past 1, clamped), pointer_over_gui is True in those frames, and the up also releases the mouse button in the frame. tests in tasks 1, 7 and 8
  • An emit from a handler while the queue drains. The Button's click handler emits throw: it is delivered the frame after the click event, which is itself the frame after the pointer went down. Two frames, on all three sides. tests in tasks 4 and 10
  • Two pointers at once. A thumb holds the Joystick while another finger taps the Button: the Joystick keeps its capture and its value, the Button clicks once, and the Joystick goes back to (0, 0) only when its own pointer lifts. tests in tasks 1, 7 and 11
  • Frame code writes a widget the user is dragging. A system sets GRAVITY_SLIDER.value = 6.0 while the pointer drags it: the page draws 6.0 this frame, the next move sets the value from the pointer again, and the write queues no event, as on the desktop. test in task 7
  • An outside emit before the first frame or while the tab is frozen. A host page posts a message while the page loads, or while run --web holds the tab frozen: it waits in the frame builder and enters the next frame taken; a message from a window other than the parent is ignored. test in task 9

Open questions, settled

The maintainer settled all three questions on 2026-11-07 by accepting each recommendation. Each one keeps its question; its last paragraph is now the decision.

1 · Fixed timestep and engine.elapsed on the desktopsettled · maintainer

Under set_fixed_timestep, Engine.run's frames never advance engine.elapsed, so engine.delay() and elapsed_at() never resolve there; only render_frame adds the dt (src/manifoldx/engine.py:1477). The page adds every frame's dt.

decisionThe fixed timestep is out of 5b, since no replay runs that mode. Adding the fixed dt in _compute_dt on the desktop is filed as gia-uh/manifoldx#168.

2 · The arrow keys on a desktop Slidersettled · maintainer

Task 1 makes the arrow keys step a Slider after it is clicked, on the desktop as in the page. An app that steers with the arrows sees the Slider move until a click lands elsewhere. The alternative was to drop arrow keys from Q4's decision, which loses the page's keyboard access to the Slider.

decisionThe arrow keys step a clicked Slider on the desktop, and the CHANGELOG lists it under Changed as a behaviour change.

3 · Panels anchored elsewhere than top-leftsettled · maintainer

The desktop hit-tests top-left panels only (manifoldx#13), so a Button in a bottom-right panel clicks in the page and not on the desktop.

decisionweb_crowd's panels stay top-left in 5b, and #13 (anchors on the desktop) is fixed before plan 5c, whose second consumer puts its buttons in a column on a side.
