Native World execution

manifoldx._core_native.NativeRuntime executes the existing native World on its calling thread with Python detached. NumPy prepares owned input once; Rust keeps the columns and runs every frame. A separate Python async producer may submit commands. No Python entity or frame callbacks run.

This explicit runtime demonstrates native column execution. Engine bootstrap remains unsupported. There is no renderer, GPU execution, vehicle physics, general scheduler or game integration in this slice.

Run the installed example

Install the built wheel, copy examples/native_runtime.py outside the checkout, then run it with that environment's interpreter:

python -I native_runtime.py --entities 100000 --seconds 2

The compiled extension is required. The example first asserts deterministic FIFO behavior and atomic stale rejection, then runs a paced loop on the main thread. Its producer sleeps, holds Python busy, fills the queue, and stops execution. Exact final state is checked using the actual command boundary numbers. Timing varies and is descriptive. The producer is always joined. --deterministic-only omits pacing; --control-drop-first deliberately loses a submission and must fail.

Ownership and lifecycle

Create NativeRuntime(world, position, velocity, capacity=64, max_rows=4096, batches_per_frame=8). It transfers the same World exclusively; every direct World operation rejects until close() or runtime drop returns it. Native integration requires distinct, equal, nonzero-width f32 columns. Only rows carrying both components are integrated, in ascending slot order, as position += velocity * dt. Nonmembers are untouched.

run(frames, dt, pace_hz=None) runs once, on the caller's thread, with finite positive dt and a positive frame limit. Pacing adds interruptible wall time without changing dt or adding catch-up steps. phase is ready, running or stopped. No native worker is created. Python owns any producer thread and its event loop, exception handling and join.

stop() needs no queue credit and wakes pacing. A frame already selected completes. Pending commands are cancelled in FIFO order, each with a completion. The frame limit has the same pending disposition. Stop before run cancels immediately. close() during run rejects; stop, let run return, then close. A second run or run after close rejects. Drop restores the World and creates no thread to join. Execution failures stop admission and retain the first error; batch rejection does not stop later valid work.

Commands and boundary order

APIOwned operation
submit_rows(name, handles, data)Atomic replacement of one component's member rows.
submit_destroy(handles)Atomic destroy of live generation-bearing identities.
request_read(name, handles)Selected owned component readback at its exact FIFO position.

Handles are C-contiguous uint64 (n,2); values are C-contiguous f32/u32 (n,width), matching the registered schema. Buffers are copied and released before admission, without a World or queue lock. Bounds are checked before copying. Each operation is limited by max_rows and 4 MiB of owned handles/payload or selected readback. Schema widths are at most 256. Capacity bounds queued commands plus unconsumed outcomes; producers must consume results to regain credits. Memory is therefore bounded by capacity and the per-operation byte cap, plus producer-local conversion storage.

Admission returns a dictionary with status admitted and a monotonically increasing sequence, or full, stopped, or error. Invalid Python descriptors raise before admission. At apply time, native generation, component, membership and payload validation reject the whole batch atomically. No callback reports failure.

Each boundary selects at most batches_per_frame already admitted operations, applies them in sequence order, then integrates once and publishes counters. Admissions after selection wait for the next boundary. Reads observe preceding commands and preceding frames, before this boundary's integration. take_outcome() consumes one FIFO result or returns None; results contain sequence, zero-based frame, status and optional error or owned handles/membership/data bytes. A cancelled result's frame is the number of completed frames. Returned buffers remain independent of all later World mutations.

Measurements and gates

stats() copies aggregated counters only: frames, native_steps, rows_integrated, admitted/applied/rejected/cancelled, full, backlog, outcomes, first_error, native_ns, frame_ns, max_frame_ns, paced_ns and wall_ns. Native time measures integration; frame time includes command application and integration; paced time measures waits; wall time measures run. No per-frame history accumulates. During execution wall_ns is finalized only on return.

bytes_in counts copied handle/payload bytes submitted, including full/stopped attempts. readback_bytes counts owned readback bytes produced; bytes_out counts readbacks consumed. These exclude dictionary metadata and NumPy setup transfers through direct World methods. No full-entity snapshot occurs per frame.

make native-check covers scoped Rust checks. The existing installed-wheel verifier runs this example, its lost-command negative control, extension removal (hard failure), restoration, and existing packaging gates. This proves native CPU execution and ownership on the tested interpreter/platform, not graphics or performance promotion.
